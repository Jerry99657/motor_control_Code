# NES 后续优化路线

> 状态：暂缓实施。本文只记录后续方向，当前稳定版本不修改。

## 当前基础

目前工程已经具备：

- iNES 1.0 ROM 加载；
- Mapper 0、1、2、3；
- W25Q64 ROM 缓存、CRC32 校验和缓存快速命中；
- 约 60 Hz 模拟、约 30 FPS LCD 异步显示；
- 开发板实体按键与 ESP32-C3 手机 NES 手柄同时输入；
- 手机端独立长按 RESET；
- 带电池标志 ROM 的 8 KiB PRG-RAM `.sav` 存档；
- KEY3 正常存档退出、KEY2 紧急退出；
- CPU、PPU、Mapper 和 FatFs 故障诊断。

后续优化应继续保持以下边界：不加入音频输出，不降低 KEY2/KEY3 的本地安全优先级，不让 NES 手机帧进入电机控制路径。

## 推荐实施顺序

### 第一阶段：即时存档与读档

当前 `.sav` 只保存卡带电池 PRG-RAM，不能恢复 CPU、PPU 和关卡运行现场。下一步优先增加即时状态文件：

- 第一版只提供一个槽，稳定后扩展为 3 个槽；
- 手机 NES 页面增加 `SAVE STATE` 和 `LOAD STATE`；
- 保存操作必须安排在完整帧边界；
- 保存 CPU、PPU、APU 兼容状态、CPU RAM、PPU RAM、CHR-RAM、PRG-RAM、控制器和 Mapper 状态；
- 不保存 ROM 内容、ROM 指针、LCD 帧缓冲和临时绘制缓存；
- 读档后强制完整绘制下一帧，并重建所有运行时指针；
- 文件头记录格式版本、ROM CRC32、Mapper、负载长度和数据 CRC32；
- ROM CRC32 或 Mapper 不一致时拒绝加载；
- 采用 `.tmp` 写入、`f_sync` 和原子改名，避免掉电产生半文件；
- 文件建议使用 `.ns0`、`.ns1`、`.ns2` 后缀，不能与电池 `.sav` 混用。

禁止直接把整个 `NES_RuntimeContext` 原样写入文件，因为结构体中包含 ROM、帧缓冲指针、编译器填充以及可能随版本变化的内部字段。

验收条件：

1. Mapper 0/1/2/3 各选择至少一个 ROM 验证保存和恢复；
2. 读档后画面、关卡、角色位置和 Mapper Bank 与保存前一致；
3. 错误 ROM、损坏文件和旧版本状态文件能够安全拒绝；
4. 保存失败不能覆盖上一份有效状态；
5. KEY2 仍能立即退出，不被 SD 写入阻塞。

### 第二阶段：Mapper 4 / MMC3

Mapper 4 能扩大 ROM 兼容范围，但依赖更准确的 PPU 时序，建议在即时存档稳定后实施：

- 8 KiB/16 KiB PRG Bank 映射；
- 1 KiB/2 KiB CHR Bank 映射；
- PRG 模式和 CHR inversion；
- 水平/垂直镜像控制；
- PRG-RAM 使能和写保护；
- PPU A12 有效上升沿检测；
- IRQ latch、reload、enable、disable 和 CPU IRQ 请求；
- 为寄存器 `$8000-$FFFF` 建立独立读写测试。

不能简单地“每条扫描线减一次 IRQ 计数器”。正确方向是依据 PPU 图案表访问产生的 A12 边沿计数，并设置低电平最短滤波时间，否则部分游戏会出现画面抖动、分屏错误或无法运行。

验收条件：

1. Mapper 4 ROM 能正确进入标题和关卡；
2. 状态栏、分屏滚动和场景切换正常；
3. IRQ 不造成 CPU JAM 或异常高占用；
4. Mapper 0/1/2/3 没有性能和兼容性回归。

### 第三阶段：手机手柄体验

- A/B 独立连发开关；
- 连发频率可选择，例如 8、12、15 Hz；
- WebSocket 连接状态、最近输入延迟和超时释放提示；
- 横屏和全屏提示；
- SAVE、LOAD、RESET 使用长按或二次确认；
- 浏览器失焦、切换后台和断开连接时继续释放所有手机按键；
- 页面切回 ROBOT 前先发送 NES 全释放帧。

连发应由 ESP32 或 STM32 根据“连发启用状态”生成稳定节拍，不能依赖手机浏览器的高频定时器，因为浏览器进入省电调度后周期会明显抖动。

### 第四阶段：性能与准确性

- 分别统计模拟 FPS、LCD 显示 FPS、平均帧耗时和最长帧耗时；
- 根据帧耗时动态决定是否跳过显示，不能跳过 CPU/PPU 模拟；
- 改进 Sprite 0 Hit 和精灵优先级；
- 改进 PPU 滚动寄存器和渲染中途寄存器写入时序；
- 校正 NMI、APU Frame IRQ、Mapper IRQ 的先后关系；
- 为卡顿和超时记录最近 PC、Opcode、扫描线、Mapper Bank 和 IRQ 状态；
- 建立固定 ROM 回归表，每次修改后重复运行。

性能边界建议：

- 保持约 60 Hz 的游戏逻辑时钟；
- LCD 可以维持约 30 FPS，性能不足时优先降低显示帧率；
- 不为提高 LCD FPS 牺牲输入扫描或 CPU/PPU 执行完整性；
- 保留 AXI SRAM 媒体池余量，禁止为即时存档再常驻一份完整帧缓冲；
- SD 和 QSPI 操作只能在明确的保存、加载或缓存阶段执行，不能进入逐扫描线热路径。

## 暂不推荐的方向

### 音频输出

当前项目目标是稳定画面和控制。NES 音频需要额外实现 APU 通道、混音、采样缓冲、DMA 输出和音画同步，会明显增加中断、RAM 和 CPU 压力，因此继续维持无音频设计。

### 自动周期写 SD

不建议每隔数秒自动写即时状态。频繁 FatFs 写入会增加卡顿、掉电损坏窗口和 SD 卡磨损。若以后需要自动恢复，应先将状态复制到专用 RAM 快照，再由低优先级流水线写卡，并限制最短保存间隔。

### 大面积游戏叠加 UI

NES 运行时直接拥有 LCD，LVGL 暂停刷新。若加入复杂半透明菜单，需要额外合成缓冲和刷新协调。第一版即时存档应使用短暂的直接绘制提示或退出到专用页面，不应立即引入大面积 LVGL 叠加层。

## 建议的下一次开发入口

恢复优化时建议从“一槽即时存档”开始，依次完成：

1. 定义带版本和 CRC 的显式状态文件格式；
2. 实现内存状态导出和恢复，不先接 UI；
3. 为 Mapper 0 做保存/加载测试；
4. 扩展到 Mapper 1/2/3；
5. 最后加入手机端 SAVE/LOAD 长按按钮和状态提示；
6. 稳定后再扩展多槽，并开始 Mapper 4。
